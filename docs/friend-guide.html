Your Lead Ingest System, Explained

This is your system, built for Benton Drones. This guide explains what it does, how to use it, and how to run it — in plain language, no coding required. You bring the engineering brain; this fills in the software part.

What you have

Anderson — this is a lead capture system built specifically for Benton Drones. It replaces the old routine of Google Forms, PDFfiller, Google Sheets, and manually plotting addresses in Google Earth. All of that now happens in one place, automatically.

Here's the short version of what it does:

  • A customer visits your branded signup page and fills out one form — including reading and signing the waiver by typing their name.
  • The system checks the info, pinpoints the address on a map, and files everything away safely.
  • You log into a private dashboard and see every lead on a map, with totals and breakdowns.
  • With one click you download the data as a spreadsheet (CSV) or map files (GeoJSON / KML) for Google Earth.
Think of it like a well-run front desk. The old way was like having customers write their info on sticky notes, then you copying each note into a logbook, then a filing cabinet, then a map on the wall — by hand, every time. The new way is a single front-desk clerk who takes the info once, files it, marks the map, and hands you a summary whenever you ask. You never touch the paperwork.

How it works (the 30-second version)

You don't need to know code to understand the shape of this. There are exactly three pieces:

The whole system in three boxes. The form is the front door, the app is the clerk doing the work, and the database is the filing cabinet.

The three pieces, in workshop terms: the form is the intake sheet on the counter. The app (hosted on a service called Render) is the shop hand who reads the sheet, checks it's filled in correctly, and puts a pin on the map. The database (hosted on a service called Neon) is the parts bin where everything is stored, labeled, and kept safe. The app and the database live in two separate places on purpose — so if one restarts, your data is still safe in the other.

When you want to see your leads, you visit the admin dashboard — a private page that reads from the database and shows you everything on a map, with buttons to download the data.

Try it end-to-end (5 minutes)

  1. Open the signup form and fill it out like a customer would. Use a real-sounding address so the map works.
  2. Read the waiver box, tick the consent checkbox, and type your full name in the signature field.
  3. Submit. You'll see a confirmation page.
  4. Go to …/admin-login and enter the admin password. Ask Tyler for it — it's a secret that isn't written down anywhere public.
  5. Once you're in, open …/admin. Your test lead will be on the map and in the "recent leads" table.
  6. Click View on your lead to see the full record, including the signature and consent.
  7. Click CSV, GeoJSON, or KML at the top to download your leads. Open the KML file in Google Earth to see your leads plotted.

Heads up The free tier naps

The app runs on Render's free plan, which puts the app to sleep after about 15 minutes of nobody using it. The first visit after a nap takes roughly 50 seconds to wake up — the page will look like it's loading slowly, then it appears. After that it's fast. If this gets annoying, Render's paid "Starter" plan (about $7/month) keeps it awake all the time.

Run it yourself on your own computer (optional)

You never have to do this — the live app above is the real thing. But if you ever want to tinker, test an idea, or just see it run on your own machine, here's how. Think of this as running a copy of the shop in your garage: same tools, but it's your sandbox and nothing you break here affects the real one.

What you need first

  • A Mac (these steps assume macOS) with the Terminal app.
  • Python 3.11 or newer — the programming language the app is written in. To check, open Terminal and type python3 --version then press return. If it prints 3.11 or higher, you're set. If not, download it free from python.org.
  • Git — the tool that downloads the code. Type git --version; if you get a number, you have it. If not, macOS will offer to install it the first time you try.

Step 1: download the code

In Terminal, paste this and press return. It creates a folder with the whole project inside:

Terminal
git clone https://github.com/t-granlund/Benton-Drones-Lead-Ingest.git
cd Benton-Drones-Lead-Ingest

Step 2: set up the database

Terminal
python3 scripts/init_db.py

This creates an empty, ready-to-use database file. Locally it's a single file on your disk (SQLite) — no separate service needed.

Step 3: start it

Terminal
ADMIN_PASSWORD=pick-a-password python3 -m lead_ingest.server

Replace pick-a-password with any password you like — this becomes your local admin password. You'll see a line saying it's serving on http://127.0.0.1:8000. That address means "this computer." Leave this Terminal window open while you use it.

Step 4: use it in your browser

AddressWhat it is
http://127.0.0.1:8000/signupThe signup form (your local copy).
http://127.0.0.1:8000/admin-loginAdmin login (use the password from Step 3).
http://127.0.0.1:8000/adminYour local dashboard.

To stop the local app, click back into the Terminal window and press Ctrl + C.

Local vs. live, in workshop terms: the live app is the storefront — customers actually walk in there. Running it locally is a workbench in your garage where you can take things apart safely. They look and behave the same, but the workbench has its own separate parts bin (a local database file), so your experiments never touch real customer data.

The moving parts, and who runs them

When something isn't working, it helps to know which "shop" is responsible for which part. There are three, and they're run by three different companies:

The app and database are deliberately separate so that restarting or updating the app never touches your stored leads. The app reads the database's address from a private setting (DATABASE_URL) and connects to it automatically — you never have to wire them together by hand.

Good to know

Legal The waiver wording is a placeholder

The waiver text customers see right now is placeholder wording, clearly marked as such. The system for capturing signatures and consent is solid — it records the exact text shown, the typed name, and a timestamp every single time. But the words themselves need a lawyer's sign-off before you use this with real customers. That's a one-time swap of text, not a rebuild.

Security Keep secrets out of public view

The admin password, the database address, and the security keys live only in private settings on Render — never in the code, and never in these public docs. If you run it locally, the password you type in Terminal stays on your machine. Don't email the admin password or paste it into any shared doc.

Privacy Your data is yours

Leads are stored in your own Neon database, not in a third-party form tool. Nothing is shared with Google, and no customer info sits in a spreadsheet that could get forwarded around. Exports only happen when you, the logged-in admin, click download.
